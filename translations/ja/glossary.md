DeepSeek Harness のドメイン語彙は、1つの概念につき1つの正規用語を使います。用語は標準的な Markdown アンカーで項目にリンクし、実装の詳細はパッケージ README と Agent Notes に置きます。

## capability-seam

- **seam（シーム）** — 3つの役割を持つ*交換可能なケイパビリティ*です。**サービス定義**（Cordis の `Service` で、`ctx.<key>` と語彙型を所有するもの。`ShellExecutor` のような抽象クラス、または `WebRuntime` のような具象レジストリであり、TypeScript の `interface` ではない）、1つ以上の**サービス・プロバイダー**、サービスを注入する1つ以上の**コンシューマー**から成ります。`packages/shell` が正規の例です。`dsh-shell`（サービス定義）、`dsh-bash-local` / `dsh-bash-sandbox`（プロバイダー）、`dsh-tool-bash`（コンシューマー）があります。役割は独立して進化する場合は通常別パッケージになりますが、1つの関心事である場合は1つのパッケージが複数の役割を所有できます（`dsh-user-approval` は承認シームのサービス定義と具象実装を1つのパッケージで所有します）。シームは完全なケイパビリティであり、1つの役割ではありません。この意味に限定して用語を使い、構成要素はその役割、クラス、サービス、コントラクト、拡張ポイントで呼んでください。

## agent-scope

- **scope（スコープ）** — エージェント単位の登録の単位です。コントリビューション（ツール、プロンプト・セクション、変数、制限、リスナー）は、*グローバル*（すべてのエージェントに見える）か、*スコープ付き*（ちょうど1つの[スコープ・キー](#scope-key)が所有する）のどちらかです。2レベルでフラットです。スコープ付き登録はサブエージェントに継承されません。サブツリーの振る舞いは[リネージ](#lineage)データで表現し、スコープ構造では表現しません。
- **scope key（スコープ・キー）** — スコープがキーとする不透明な同一性で、オブジェクト同一性で比較されます。harness の慣例では、ライブなエージェントが自身のスコープのキーです。<a id="scope-key"></a>
- **agent context（`agent.ctx`）** — エージェントのスコープ付きコンテキストです。これを通じた登録はスコープ可視かつスコープ寿命（1つの事実が両方を駆動する）で、その上のリスナーはそのエージェントのスコープ・フィルタ済みディスパッチに参加します。レジストリ対象のイベントは、独自のイベント契約の下で意図的にフィルタされないままにできます。
- **scope carrier（スコープ・キャリア）** — スコープ・フィルタ済みディスパッチが運ぶ `thisArg`（`scopeTarget` が構築）です。そのフィルターは、タグなしリスナーと対象自身のリスナーを通します。*対象なし*のキャリア（キーなし）は、タグなしリスナーだけを通します。
- **scoped dispatch（スコープ付きディスパッチ）** — ルールです。あるエージェントの活動に関するイベントは、そのエージェントのキャリアでディスパッチします。レジストリ自体に関するイベント（ツールが追加された）は*レジストリ対象*であり、フィルタされません。
- **shadowing（シャドウイング）** — 最も具体的なものが勝つ名前解決です。スコープ付きのツール／セクション／変数は、そのスコープだけで同名のグローバル定義を置き換えます。エージェント単位のペルソナとツール・バリアントの仕組みです。
- **restriction / scope-local registration（制限 / スコープ・ローカル登録）** — 制限（`tools.restrict`）は、1つのスコープのためにグローバル・ツール・セットをフィルタします（交差で合成）。スコープ・ローカル登録はそのフィルタの後にマージされます。フィルタで除外されたグローバル・ツールは、プロンプトから消え、実行も拒否され、存在しないツールと区別できません。
- **setup window（セットアップ・ウィンドウ）** — 作成者がエージェントのスコープ世界を構成する作成スロットです（`CreateAgentOptions.setup`）。スコープとエージェント・オブジェクトが存在するが、エージェントやセッションが公開される前、`agent/created` が発火する前、最初のプロンプトが組み立てられる前です。セットアップは登録を行い、エージェントを駆動しません。
- **lineage（リネージ）** — 親子の事実をデータとして運びます（`parentSession`、永続的な `delegationDepth`、ランタイムの `subagentDepth`）。可視性には影響しません。<a id="lineage"></a>

## goal

- **goal（ゴール）** — 既存のセッションに付随する1つの永続的な完了目的です。リビジョン付きの `active` / `paused` / `blocked` / `complete` フェーズとゴール・ラウンド上限を持ちます。`blocked` はポリシー・コードと説明を保持します。ゴールは状態であり、スケジューラーでも別の会話でもありません。セッション・ログがその source of truth です。
- **goal round（ゴール・ラウンド）** — 現在のゴールに対して受け入れられた1つの継続サイクルです。同一セッションのドライバーは、ゴール・ラウンドを1つのゴール由来の[ターン](#turn)として具体化し、そのターンは0個以上のステップを含められます。同じセッション内の無関係な人間のターンは、ゴール・ラウンド上限を消費しません。<a id="goal-round"></a>
- **goal activation（ゴール・アクティベーション）** — 継続コンシューマーが別のゴール・ラウンドを受け入れるためのプロセス・ローカルな許可です。アクティベーションは `armed` か `disarmed` で、永続リプレイには意図的に含まれません。そのため resume と fork は、自動作業の前に `/goal` またはモデル・ツールを通じた人間認可の resume 変更を必要とします。

## human command

- **human command（ヒューマン・コマンド）** — スラッシュ接頭辞の命令で、人間向けアダプターが `ctx.commands` を通じて解釈・実行します。モデル・メッセージにはなりません。モデル向けツールや、`ctx.shell` を通じたシェル・コマンド実行とは別物です。
- **command plane（コマンド・プレーン）** — UI アダプターとコマンド・プラグインが所有する、発見、解析、ディスパッチ、キャンセル、結果レンダリングです。コマンド出力は、ハンドラーが別途永続ドメインを変更しない限り、UI 状態です。
- **goal command（ゴール・コマンド）** — `dsh-command-goal` が提供する `/goal` ヒューマン・コマンドです。現在のゴールを直接観察・変更しますが、ゴール・ドメインがすべての永続的でモデル可視の記録を所有します。

## loop hierarchy

- **turn（ターン）** — セッション内で受け入れられた入力の1回の取り出し処理（drain）です。モデルとそのツールが停止するか、終端ポリシーが介入した後に終わります。<a id="turn"></a>
- **step（ステップ）** — 1回のモデル・リクエストと、その応答が引き起こすツール実行です。ターンは0個以上のステップを含みます。<a id="step"></a>
- **round（ラウンド）** — ターンを含む外側のポリシー反復です。たとえば[ゴール・ラウンド](#goal-round)や、1回の fresh-agent Ralph 試行です。ラウンド・カウンターはそのポリシーに属し、セッション内のすべてのターンを数えるわけではありません。<a id="round"></a>
- **exchange（エクスチェンジ）** — 最初の[ステップ](#step)が人間の入力を受け入れたターンから、次にそのようなターンが来るまでの連続した[ターン](#turn)です。通知（決着したサブエージェント、ゴール・ラウンド、スケジュールなど）で起床したターンは、前のエクスチェンジに留まります。Chat の next-message folding は、最新のエクスチェンジを展開したままにします。<a id="exchange"></a>

## Ralph

- **Ralph loop（Ralph ループ）** — 不変の目的に向かって実行される、1つのフォアグラウンド fresh-agent ワークフローです。ワークフローとサブエージェントのプリミティブから構成されるモデル向けツール・ポリシーであり、同一セッションのゴール、agent-loop モード、スケジューラー、汎用ワークフロー・スクリプト機能ではありません。<a id="ralph-loop"></a>
- **Ralph round（Ralph ラウンド）** — [Ralph ループ](#ralph-loop)内の1つの fresh な子セッションです。子は親や前の子の会話シードを受け取りません。共有ワークスペースと1つの境界付き [Ralph handoff](#ralph-handoff) がラウンド間の状態を運びます。<a id="ralph-round"></a>
- **Ralph handoff（Ralph ハンドオフ）** — 継続する Ralph ラウンドから次のラウンドへ渡される、正規化された境界付き構造化レポートです。status、summary、evidence、next steps、blocker text を含みます。共有ワークスペースを権威として置き換えるのではなく、補完します。<a id="ralph-handoff"></a>
