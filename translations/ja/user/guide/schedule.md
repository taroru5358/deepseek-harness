# リマインダーをスケジュールする

## 概要

会話の中でモデルにリマインダーの作成、一覧、表示、編集、一時停止、再開、削除を依頼します。各リマインダーはそのルールで繰り返し、指示を既存の会話、1つの新しい会話、または発生ごとの新しい会話に配信します。Automation tasks ページは Host のすべてのリマインダーをリストし、作成、編集、実行、一時停止、再開、削除ができます。配信された1回限りのタスクは、明示的に削除するまで利用可能なままです。

## リマインダーを作成する

同梱の Web profile には Host Schedule サービスと Automation tasks ページが含まれます。リマインダーの作成を依頼する前に、モデル provider を設定してください。

`standard`、`cordis`、`ptc` preset は4つのリマインダー tool と、モデルに現在時刻とブラウザのタイムゾーンを与える clock コンテキストを宣言するため、これらの preset は `schedule_create`、`schedule_list`、`schedule_view`、`schedule_edit` を提供します。`minimal` preset はどちらも宣言しません。委譲されたサブエージェントは4つの tool を見ますが、各 tool は委譲されたサブエージェントからの呼び出しを拒否するため、サブエージェントはリマインダーを読み取ったり変更したりできません。

モデルにリマインダーの作成、一覧、表示、編集、一時停止、再開、削除を依頼します。モデルは作成に `schedule_create`、すべての会話のリマインダーの一覧に `schedule_list`、1つの読み取りに `schedule_view`、変更、一時停止、再開、削除に `schedule_edit` を使います。編集はリマインダー id と保存済み配信レコードを保持します。モデルが作成するリマインダーには名前、指示、UTC または IANA タイムゾーンでの開始時刻、および RFC 5545 の繰り返しルール（たとえば毎平日 09:00、または1回のみ）があります。配信先はこの会話、最初の配信が作成する1つの新しい会話、または配信ごとの新しい会話です。新しい会話はこの会話の作業ディレクトリと preset を使います。リマインダーの各配信は、前回の配信の予定時刻、または前回の Run now の少なくとも1分後に来ます。配信ごとに新しい会話を開くリマインダーは、代わりに Host の最小実行間隔（既定で1分）を待ちます。遅れた配信（たとえば Host 再起動後）は次の配信を遅らせません。

配信が作成する会話は、その作業ディレクトリに登録された Workspace に参加し、リマインダー名をタイトルにします。配信ごとに新しい会話を開くリマインダーでは、タイトルにリマインダーのルールのタイムゾーンでの起動時刻も表示されます。たとえば `Weekday digest · 2026-10-12 09:00` です。

たとえば、次のように尋ねます: 「毎日 23:00（Asia/Shanghai）に天気を確認するようリマインドして。」返信の下に、作成されたリマインダーの名前と頻度を示すカードが表示されます。Open を選ぶと右サイドバーに詳細が表示されます。頻度が Once ではなく毎日 23:00 の繰り返しであることを確認してください。1回限りのリマインダーは配信後に繰り返しになりません。リマインダーが削除されると、カードは Deleted を表示し、開かなくなります。

モデルを使わずにリマインダーを作成するには、サイドバーから Automation tasks を開き、New の横にある Choose a creation method を開き、Create manually を選びます。タスクが存在しない場合、New automation task が同じダイアログを開きます。Create manually ダイアログは、Automation task name、Automation task instruction、Run in、Linked workspace、Run time を尋ねます。ブラウザのタイムゾーンで1時間後の Once と、Create a conversation and reuse it で始まります。Run in は、最初の実行で1つの会話を作成して使い続ける Create a conversation and reuse it と、実行ごとに別の会話を作成し Host の最小実行間隔を表示する New conversation for every run を提供します。Linked workspace は、登録された各 Workspace をディレクトリとともにリストし、新しい会話が使うディレクトリの Workspace を選択します。Default workspace で始まり、既定の Workspace が登録されていない場合は最初の Workspace で始まります。Workspace が存在しない場合、Linked workspace は Ungrouped を表示し、Host プロジェクトディレクトリが使われます。新しい会話は既定の preset を使います。Create はタスクを作成してリストで選択し、Cancel は作成せずにダイアログを閉じます。Host がタスクを拒否した場合、ダイアログは入力を保持し、問題（たとえば日時が未来でなければならないこと）を表示します。

同じメニューの New と Create in a conversation は、現在または直近の Workspace に新しい会話を開きます。そこでモデルにタスクの作成を依頼します。

<a id="manage-tasks"></a>
## タスクを確認、実行、削除する

モデルにリマインダーの一覧を依頼すると、すべての会話のリマインダーがアクティブなものを先に表示します。または、id で1つのリマインダーの表示、一時停止、再開、削除を依頼します。

サイドバーから Automation tasks を開くと、会話をアクティブにせずに Session 全体のリマインダーを表示できます。タスク名、指示、またはタスクの会話の id で検索し、Task status（All、Enabled、Paused、Ended）でフィルターします。行は予定時刻順で、早いものが先です。各行はタスク名と1つの概要行を表示します。一時停止中または終了したタスクのステータス、頻度、および有効なタスクの場合は Next scheduled time とそのローカル時刻および相対時刻です。

Session のタスクとは、その Session に配信するタスク（実行ごとに新しい会話を作成するタスクの最新実行を含む）と、その Agent が作成または編集したタスクです。アイドル状態でアーカイブされていない Session 行で、Session に少なくとも1つのアクティブなタスクがある場合、時計マークが表示されます。アーカイブされた行はそのセルを空白のままにし、ライブステータスはホバーカードにのみ表示されます。アクティブなタスクを持つ Session 行を長くホバーすると、それらのタスクを最大2つまで、頻度と次回実行をデバイスのタイムゾーン時刻および相対時間で表示します。開いている Session のヘッダーは、Session にアクティブなタスクがある間、アイコンのみのリマインダー時計を表示します。これは唯一のタスクの詳細を右サイドバーに開くか、そうでなければそれらのタスクのリストを開き、各行からタスクの詳細を開くかタスクを削除できます。

タスクを選ぶと詳細が開きます。Rules はタスク名、Next run とそのローカル時刻および相対時刻（または一時停止中もしくは終了したタスクのステータス）、指示、Repeat、Run in を表示します。Run in は、既存の会話に配信するタスクでは Current linked conversation を表示します。詳細の下部は Linked session、または実行ごとに新しい会話を作成するタスクでは Latest run conversation を表示します。そのボタンは Session が利用可能でアーカイブされていない場合にその会話を開き、そうでなければ無効です。最初の実行が会話を作成する前は、エントリは Pending creation を表示します。既存の会話に配信するタスクでは、Rules はその会話がアーカイブ済み、利用不可、または読み込み中であることを示します。タスクの詳細と削除は、会話を開けない場合でも利用できます。タスクの閲覧は Session のアーカイブを解除しません。

Records を選ぶと、保存された最新20件のレコードを読み込みます。各レコードは、タスクのルールのタイムゾーン（ルールがタイムゾーンを指定しない場合はブラウザのタイムゾーン）での発生日時、その会話が利用可能な場合に配信を受け取った会話を開くボタン、および保存された指示を表示します。Expand は長い指示を完全に表示します。保存された指示のないレコードは、代わりに現在の指示を表示することはありません。Load more は次のページを追加します。レコードは、時計が逆戻りしても保存された新しい順に従います。モデルの実行結果を表すものではありません。左右の矢印キーと Home/End でフォーカス中のタブを切り替えます。

空のレコードビューは、成功したクエリが保存済みレコードを返さなかったことを意味します。読み込み中、リクエスト失敗、タスクの欠落、無効な古いレコードカーソルには別々のメッセージがあります。リクエスト失敗またはタスク欠落の応答の後は Retry を使ってください。無効なカーソルの後は Refresh で最新ページを再読み込みしてください。リクエストが失敗している間、以前に読み込んだレコードが警告付きで表示されたままになることがあります。新しい最新配信は最新ページを更新します。離れたタスクやビューの遅延応答は現在のビューを置き換えません。

保持期間によって以前のレコードが削除された場合、最後のページは以前の配信レコードが消去されたことを示し、Retention rules は各タスクが保持するレコード数と日数を表示します。保存された履歴のない古いタスクは、新しい配信がレコードを追加するまで、指示なしで最新の配信のみを表示します。保存されなかった以前のレコードと指示スナップショットは復元できません。

アクティブなタスクはスケジューリングに参加します。一時停止中および終了したタスクは次の配信をスケジュールしません。1回限りのタスクは、リマインダーが会話の受信箱に永続的に書き込まれた後に終了し、繰り返しタスクはそのルールの最後の発生後に終了します。終了したタスクを見つけるには、Task status で All または Ended を選びます。Session ヘッダーの時計、行のマーク、ホバーカードはアクティブなタスクのみを表示するため、それらのビューから消えてもタスクが削除されたことを意味しません。

詳細の Pause はアクティブなタスクの将来の配信を停止し、Resume は一時停止中のタスクを再開します。Automation task actions メニューの Run now は、Host に指示を今すぐ1回配信するよう求め、次回の予定実行を保持します。一時停止中または終了したタスクでも同様です。既存の会話または1つの新しい会話に配信するタスクの配信がキューに入っているか実行中は、Edit、Pause、Resume、Run now、Delete task が無効になり、詳細はタスクがキュー済みまたは実行中であり、その会話で管理することを示します。詳細下部のボタンがその会話を開きます。実行ごとに新しい会話を作成するタスクはこのように無効化されず、その実行は並行して続きます。配信後、Run now はタスクの最小配信間隔が終わるまで無効のままです。間隔だけがそれを保持している間は、Run now にポインターを置くかキーボードで移動すると、いつ利用可能になるかを確認できます。これらの理由のいずれかで Host が実行を拒否した場合、詳細はタスクがキュー済み、実行中、またはちょうど配信されたことを示します。Run now は、タスクが配信する会話がアーカイブされている間も無効です。タスクの指示がそこで待っている間に会話を停止すると、次のメッセージ、タスクの次回の予定実行、または Run now が開始するまで指示はキューに残ります。

Automation task actions メニューから Delete task を選び、確認すると、将来の配信を停止してタスクをリストから削除します。一時停止中または終了したタスクも同様です。削除はタスクを保存済み配信レコードとともに削除するため、タスクの保存履歴は失われます。削除を確認すると、アプリ全体の通知で結果が報告されます。削除された場合は詳細も閉じ、失敗した場合はタスクを残して再試行できます。会話を削除したり、すでにそこにキューされたメッセージを取り消したりはしません。行は、成功したクエリが残りのタスクを確認するまで表示されたままです。クエリが失敗した場合、Retry がカタログを再読み込みします。エラーは空の成功結果ではありません。

<a id="edit-timing"></a>
## タスクを編集する

モデルにリマインダーの名前、指示、繰り返しルール、配信先の変更、または一時停止や再開を依頼します。変更はリマインダー id と保存済み配信レコードを保持します。

Automation tasks でタスクを選び、Edit を選んで Automation task name、Automation task instruction、Run in、Linked workspace、Run time を変更します。一時停止中または終了したタスクも同様です。編集は Save changes を選ぶまでローカルドラフトに残ります。編集はタスク id、最新の配信レシート、すべての保存済み配信レコードを保持します。ルールを変更すると、終了したタスクは再びアクティブになり、一時停止中のタスクは一時停止のままです。既存の会話に配信するタスクでは、Run in は Current linked conversation を表示します。別のオプションを選ぶと、以降の実行が会話を作成し、Create manually と同様に Linked workspace を初期値に設定します。タスクは Workspace が同じ間は保存された preset を保持し、Workspace を変更すると既定の preset を使います。

- Once: Date は月カレンダーを開き、Time は Hour、Minute、Second 列を開き、Time zone がそれらを解釈します。タスクは1回実行してから終了します。
- Every N minutes と Every N hours: Interval は分または時間の数（最低1）を設定します。間隔はタスクを保存した分から数えます。
- Every day: Interval は日数を設定し、Time は Hour と Minute 列を開きます。
- Weekly と Monday to Friday: Interval は週数を設定し、Weekday は曜日を選択し、Time は Hour、Minute、Second 列を開きます。Monday to Friday はその5日を一度に選択します。
- Monthly: Interval は月数を設定し、Day of the month は1から31までの日付を選択し、Time は Hour、Minute、Second 列を開きます。選択した日付のない月はその最終日に実行されます。
- Custom: Custom rule はルールテキストを保持します。他の選択肢で再現できないルールは Custom で開きます。編集可能なルールテキストのない既存タスクは元の頻度を表示し、置き換えを保存するまでそのタイミングを保持します。

Time zone は最近選択したゾーンを先にリストし、システムゾーンをマークし、UTC オフセット、IANA ID、または都市で検索します。ガイド付きの選択肢と、別のゾーンを使う Custom 式に表示されます。それ以外の場合、Custom ルールテキストがゾーンを提供します。

フィールドはローカルドラフトのみを変更します。編集中、詳細の下部に Unsaved changes と Cancel、Save changes が表示されます。Save changes は変更されたフィールドのみを1回の更新で送信し、Cancel は保存された値を復元します。保存はタイミングが変更された場合にのみ新しいルールを送信します。名前または指示が空の場合、またはガイド付きの選択が不完全な場合、Save changes は無効のままです。Host は保存時に提供された Custom ルールを検証し、無効なテキストはドラフトを保持してエラーを表示します。保存中はフィールドが無効になります。詳細を離れても、すでに開始された Host の書き込みはロールバックされません。

カタログの更新はドラフトを変更しません。保存が届く前に配信や別の編集がタスクを変更した場合、Host は保存を拒否して何も変更しません。詳細はタスクが別の場所で変更されたことを示し、Load latest version がドラフトを最新バージョンに置き換え、それまでは Save changes が無効のままです。別の保存が失敗した場合、ドラフトは残り、詳細は再試行を求めます。結果が不明な更新を再試行する前にタスクを確認してください。受け入れられた更新はカタログを更新します。詳細を閉じた後やタスクを切り替えた後の遅延応答は現在のビューを置き換えません。

<a id="timing-and-delivery"></a>
## タイミングと配信のリファレンス

リマインダーは、Session が開かれていなくても保存されたままです。Host の実行中、リマインダーが期限になると対象 Session を復元または作成し、現在の作業を中断せずにフォローアップをキューに入れます。再起動すると保存済みタスクを確認し、期限切れの1回限りタスク、または各繰り返しタスクの最も新しく逃した発生のみを送信します。Host を閉じると、再び起動するまでスケジューリングが停止します。同じ Session の期限の来た繰り返しタスクは1つのメッセージを共有できます。

IANA ゾーンの繰り返しルールはローカルの壁時計時刻に従います。存在しないローカル時刻はスキップし、繰り返されたローカル時刻は早い方の瞬間を使います。既存のタスクは新しいルールを保存するまでタイミングを保持します。固定レートのリマインダーは作成時刻に合わせたままになり、毎日、毎週、cron のリマインダーは IANA ゾーンで保存されたローカル時刻に従います。ブラウザは自然言語リクエストを解釈するために自身のゾーンを提供します。ゾーンを明示すると曖昧さを避けられます。Automation tasks ページはすべての次回実行をブラウザゾーンの時計として表示し、頻度テキストはルールのゾーンがブラウザのゾーンと異なる場合にそのゾーンを明示します。ゾーンを指定しないルールはブラウザのゾーンを使います。

保存済み配信レコードは、会話の受信箱に永続化されたメッセージを確認するものであり、モデルが要求された作業を完了したことを確認するものではありません。受信箱の永続化またはタスク書き込みに失敗した場合、保存レコードは追加されません。受信箱の永続化後のクラッシュやタスク書き込みの失敗は、配信されたメッセージを記録せずに残し、配信を繰り返す可能性があります。exactly-once 配信は保証されません。Host を閉じると、会話の受信箱でまだ待っている各メッセージは破棄されます。保存レコードは残り、モデルはそのメッセージを決して受け取らず、Host はそれを再送しません。これは実行履歴でも外部通知チャネルでもありません。

保存済みレコードは、確認応答が追加されるときに刈り込まれます。Host は、確認応答時刻が設定された `deliveryHistoryDays` ウィンドウ内（追加されたレシートの `deliveredAt` から遡って測定）に入り、かつ最新の `deliveryHistoryRecords` レコード以内のレコードを保持します。最新のレシートは常に残り、刈り込まれたウィンドウは以前のレコードを利用不可としてマークします。Host は保持履歴をメモリに持ち、確認応答ごとに完全なタスク行を書き換えます。ページネーションは返されるレコード数を制限し、保持履歴や指示のバイト数は制限しません。

名前、指示、タイミング、配信先の編集、一時停止、再開は、モデルには `schedule_edit` を通じて、Automation tasks ページにはすべてのリマインダーについて利用できます。どちらもクロス Session の中継ワークフローではありません。変更は、Agent が読み込まれている関係する各会話の次のモデルリクエストに通知を追加します。ただし変更を行った会話は除きます。古い Session ログにのみ記録されたリマインダーは自動的にスケジュールされません。まだ必要なものは再作成してください。以前に削除されたタスクレコードは再構築されません。
