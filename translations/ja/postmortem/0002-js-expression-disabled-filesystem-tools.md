# ポストモーテム 0002: ファイルシステムのスナップショットツールが恒久的に無効化された

ステータス: 解決済み

## エグゼクティブ・サマリー

ACP のサンプルは `disabled: !!js ...` でファイルシステムプラグインを条件付きで有効化しようとしたが、Cordis が JavaScript 式を評価するのはプラグインの `config` 内だけである。生の式オブジェクトは truthy だったため、ファイルシステムスタックは常に無効になっていた。さらにスナップショットの更新が `UNKNOWN_TOOL` の結果を新しい期待出力として受け入れた。修正では明示的なファイルシステム overlay を使い、静的設定とスナップショット結果のガードを追加した。

## 概要

デフォルトの ACP 構成は意図的に bash 専用である。そのサンドボックスはインプロセスのファイルシステムプロバイダを閉じ込められないからだ。ファイルシステムのスナップショットシナリオは依然として `read`、`write`、`edit` を必要とするため、それらのプラグインはデフォルトの `cordis.yml` に置かれ、`disabled` 式によってフルアクセスの起動とスナップショットのときだけ有効化される想定だった。

Cordis の Include は各 `!!js` スカラーを式オブジェクトにパースした。Loader はプラグインの `config` を再帰的に補間したが、`disabled` のようなエントリメタデータはそのまま消費した。そのためすべてのファイルシステムエントリが truthy なオブジェクトを見て、どのモードでも無効のままになった。

## 影響

7つのファイルシステムシナリオと混在ワークスペース編集シナリオが、レジストリに存在しないツールを呼んでいた。構造化されたセッションログには code `UNKNOWN_TOOL` の `ToolNotFoundError` が記録され、stdout には汎用の失敗ツールカードが描画された。スナップショットスイートが通ったのは、両方の出力が更新後のフィクスチャと一致したからであり、ファイルシステムの振る舞いが成功したことを示すものではない。それはリグレッションの決定論的再生を証明していたにすぎない。

実際に閉じ込められたデフォルト構成が意図しないファイルシステムアクセスを得ることはなかった。素朴な補間修正はそのリスクを生んでいただろう。パーミッションプリセットは実行時に bash サンドボックスと approval 状態を更新するが、ファイルシステムスタックのマウント・アンマウント・閉じ込めはできない。

## タイムライン

- PR #261 が ACP 構成を統合し、条件付きファイルシステムエントリを導入するとともにファイルシステムのスナップショットを更新した。
- ユニット、カバレッジ、スナップショット、ドキュメント、ビルド、hygiene のすべてのチェックが通った。
- 更新後のファイルシステム期待出力をレビューしたところ、汎用の失敗カードと構造化された `UNKNOWN_TOOL` の結果が見つかった。
- 実際の Loader 起動により、すべての `disabled` 値が式オブジェクトのままであり、ファイルシステムの fiber がすべて存在しないことを確認した。

## 根本原因

実装は `!!js` が Loader エントリ全体に適用されると想定していた。実際に適用されるのは `entry.options.config` だけである。`Entry._resolveConfig()` がそのフィールドを補間し、`Entry.disabled` は補間なしで `entry.options.disabled` を判定する。YAML タグは構文的に妥当だったため、ロード時に診断は出なかった。

スナップショットフレームワークは、決定論的なトランスクリプトをすべて妥当な振る舞いとして扱った。ヘッダーの pin は合成されたツールスキーマを検証していたが、ファイルシステムシナリオはデフォルト構成の pin を共有していたため、必要なツールが登録されていることを独立に証明していなかった。更新処理は、不足ツールを拒否する意味的な assert より前に、期待 stdout とセッションログを書き換えた。

## 追加したガードレール

- ファイルシステムシナリオは `fs.cordis.yml` を起動する。ペアになる replay 設定と独自のリクエストヘッダークラスを持つ、明示的で固定されたフルアクセス overlay である。
- [`AGENTS.md`](../../../AGENTS.md) と [Cordis 入門](../cordis-primer.md#loader-configuration) は、`!!js` がプラグインの `config` とエントリの `disabled` の下で有効であると述べている。他のエントリメタデータはリテラルのままなので、条件付き構成には overlay を使う。
- `verify-cordis-config` はリポジトリの Cordis YAML をパースし、include パッチや挿入されたエントリを含む Loader エントリメタデータ内の式ノードを拒否する。
- `dsh-session-snapshot` は、新規実行およびコミット済みセッションフィクスチャ内の構造化された `UNKNOWN_TOOL` 結果を、期待出力としてコミットされる前に拒否する。

## 教訓

- 構文的に受け入れられた設定値が、その場所で評価されるとは限らない。どのフィールドが補間されるかを正確に文書化し、検証すること。
- スナップショットの更新はフィクスチャの生成であり、正しさのレビューではない。登録済みツールの欠落のような意味的な不可能性には、期待出力から独立した assert が必要である。
- パーミッション制御は、実際に統制するケイパビリティだけを記述しなければならない。構成時のファイルシステムアクセスを、実行時の bash 専用プリセットに安全に追従させることはできない。
